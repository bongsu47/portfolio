# 변수 할당

변수 할당 노드는 변수 값을 변경합니다.

<figure><img src="../../../../.gitbook/assets/image (16).png" alt="" width="277"><figcaption></figcaption></figure>

새 값을 저장하거나 계산 결과로 값을 갱신할 수 있습니다.\
루프 노드와 함께 사용해 반복마다 값을 업데이트할 수 있습니다.

### 역할

워크플로우 실행 중 기존 변수 값을 직접 변경합니다.\
다른 노드가 새 결과를 생성하는 것과 다릅니다.

{% hint style="info" %}
**변경 가능한 변수**

변수 할당 노드는 **대화 변수**와 **루프 변수**를 변경합니다.\
일반 노드의 출력 변수는 변경할 수 없습니다.

* **대화 변수**: 챗플로우에서 대화가 유지되는 동안 값을 보존합니다.
* **루프 변수**: 루프 노드에서 정의하며, 반복 중 값을 갱신합니다.
{% endhint %}

### 대화 변수

대화 변수는 챗플로우에서 대화 중 값을 유지하는 변수입니다.

일반 워크플로우는 실행이 끝나면 변수 값이 사라집니다.\
챗플로우는 저장한 값을 이후 대화에서도 사용할 수 있습니다.

예를 들어 다음처럼 사용할 수 있습니다.

* 사용자가 이름을 말하면 `user_name`에 저장합니다.
* 이후 응답에서 `user_name`을 사용해 이름을 부릅니다.

대화 변수로 사용자의 선택이나 진행 상태를 관리할 수 있습니다.

#### 대화 변수 추가

워크플로우 편집 화면의 오른쪽 패널에서 대화 변수를 추가합니다.

<figure><img src="../../../../.gitbook/assets/image (17).png" alt="" width="392"><figcaption></figcaption></figure>

1. 오른쪽 패널에서 **앱 조건 설정**을 선택합니다.
2. **대화 조건 설정** 탭을 선택합니다.
3. **+ 변수 추가**를 선택합니다.
4. 변수 정보를 입력합니다.

| 항목  | 설명                            | 예시                              |
| --- | ----------------------------- | ------------------------------- |
| 이름  | 변수를 구분하는 식별자 (영문, 숫자, 밑줄만 가능) | `user_name`, `selected_product` |
| 유형  | 저장할 데이터의 종류                   | 문자열, 숫자, 배열 등                   |
| 기본값 | 대화 시작 시 초기값                   | `""`, `0`, `[]`                 |
| 설명  | 변수의 용도 메모 (선택사항)              | "사용자가 선택한 제품명"                  |

5. **저장**을 선택합니다.

#### 지원 데이터 유형

| 유형  | 설명                  | 기본값 예시  |
| --- | ------------------- | ------- |
| 문자열 | 텍스트                 | `""`    |
| 숫자  | 정수 또는 소수            | `0`     |
| 불리언 | 참/거짓                | `false` |
| 객체  | 여러 속성을 가진 데이터       | `{}`    |
| 배열  | 목록 (문자열, 숫자, 객체 배열) | `[]`    |

{% hint style="info" %}
**대화 조건 설정과 실행 조건 설정**

앱 조건 설정에는 두 탭이 있습니다.

* **대화 조건 설정**: 대화 중 정보를 저장합니다. 변수 할당 노드로 값을 변경할 수 있습니다.
* **실행 조건 설정**: API 키, 비밀번호 같은 민감한 정보를 안전하게 저장합니다.

대화 중 값이 바뀌면 **대화 조건 설정**을 사용하세요.\
변경하지 않는 설정값에는 **실행 조건 설정**을 사용하세요.
{% endhint %}

#### 대화 변수와 메모리 비교

챗플로우에는 대화 변수와 LLM 노드의 메모리가 있습니다.\
두 기능의 역할은 다릅니다.

**메모리**는 이전 대화 기록을 LLM에 전달합니다.\
LLM이 대화 흐름을 참고하는 용도이며, 다른 노드에서 참조할 수 없습니다.

**대화 변수**는 제작자가 직접 정의합니다.\
변수 할당으로 값을 저장하고 다른 노드에서 참조할 수 있습니다.

|                | 대화 변수                            | 메모리 (LLM 노드 설정)           |
| -------------- | -------------------------------- | ------------------------- |
| **무엇인가요?**     | 제작자가 직접 만드는 변수                   | LLM 노드에 이전 대화 기록을 전달하는 기능 |
| **설정 위치**      | 앱 조건 설정 > 대화 조건 설정               | LLM 노드 > 메모리 활성화          |
| **기억하는 내용**    | 제작자가 지정한 특정 값 (예: 선택한 제품, 진행 단계) | 이전 대화의 질문-답변 쌍 전체         |
| **값 변경**       | 변수 할당 노드로 직접 변경                  | 자동 (대화가 쌓일수록 기록이 늘어남)     |
| **다른 노드에서 사용** | 가능 (조건 노드, 템플릿 노드 등에서 참조)        | 불가 (해당 LLM 노드만 참고)        |

{% hint style="info" %}
**사용 기준**

* 이전 대화 내용을 LLM이 이해해야 하면 **메모리**를 사용합니다.
* 진행 단계나 선택 항목을 추적하려면 **대화 변수**를 사용합니다.
* 두 기능을 함께 사용할 수 있습니다.
{% endhint %}

### 설정

<figure><img src="../../../../.gitbook/assets/image (18).png" alt="" width="366"><figcaption></figcaption></figure>

#### 대상 변수

값을 변경할 대화 변수 또는 루프 변수를 선택합니다.

#### 연산 방식

변수 값을 변경할 방식을 선택합니다.

| 연산       | 설명                                            | 예시                                   |
| -------- | --------------------------------------------- | ------------------------------------ |
| **덮어쓰기** | 기존 값을 지우고 새 값으로 교체합니다                         | `"홍길동"` → `"김철수"`                    |
| **값 지정** | 변수에 값을 설정합니다                                  | 빈 변수에 `"서울"` 지정                      |
| **누적**   | 기존 값에 새 값을 이어 붙입니다. 배열이면 항목이 추가되고, 숫자면 더해집니다  | `["사과"]` + `"바나나"` → `["사과", "바나나"]` |
| **지우기**  | 값을 비웁니다. 문자열은 `""`, 숫자는 `0`, 배열은 `[]`로 초기화됩니다 | `"홍길동"` → `""`                       |

{% hint style="info" %}
**연산 선택**

* 새 값으로 바꾸려면 **덮어쓰기**를 사용합니다.
* 배열에 항목을 쌓거나 숫자를 합산하려면 **누적**을 사용합니다.
* 값을 초기화하려면 **지우기**를 사용합니다.
{% endhint %}

#### 값 지정 방식

새 값을 가져올 방식을 선택합니다.

| 방식   | 설명              | 사용 예시                 |
| ---- | --------------- | --------------------- |
| 고정 값 | 직접 입력한 값을 사용    | 단계를 `"완료"`로 변경할 때     |
| 변수   | 다른 노드의 결과 값을 사용 | LLM의 출력을 대화 변수에 저장할 때 |

#### 여러 변수 동시 변경

오른쪽의 `+`로 하나의 노드에서 여러 변수를 변경할 수 있습니다.

각 변수에 다른 연산을 적용할 수 있습니다.

### 출력 변수

별도 출력 변수는 생성하지 않습니다.\
대상 변수 값을 직접 변경합니다.

### 활용 예시

#### 사용자 감정에 맞춰 응대

고객 상담 챗봇에서 사용자 감정에 따라 응대 톤을 조절합니다.

**동작 방식**

> 사용자: "아까부터 계속 안 되는데요"\
> → LLM이 감정을 분석: "불만"\
> → 대화 변수 `user_mood`에 "불만" 저장\
> → 다음 응답부터 LLM에 "사용자가 불만 상태이니 더 공감하며 정중하게 응대하세요"라는 지시를 함께 전달

**구성**

```
시작 → LLM (감정 분석) → 변수 할당 (user_mood 업데이트) → LLM (응대) → 답변
```

* 대화 변수: `user_mood`(문자열) = `"보통"`
* 첫 번째 LLM 노드: 사용자의 메시지를 읽고 감정을 "만족 / 보통 / 불만 / 화남" 중 하나로 판단
* 변수 할당 노드: 판단 결과를 `user_mood`에 덮어쓰기
* 두 번째 LLM 노드: `user_mood` 값을 프롬프트에 포함하여 톤을 조절

매 대화에서 감정을 다시 분석해 응대 톤을 조절합니다.

#### 대화 중 관심 항목 수집

쇼핑 챗봇에서 관심 제품을 모아 맞춤 추천에 사용합니다.

**동작 방식**

> 사용자: "노트북 좀 볼게요" → `interested_items`에 "노트북" 추가\
> 사용자: "마우스도 필요해요" → `interested_items`에 "마우스" 추가\
> 사용자: "이제 추천해주세요" → 지금까지 모인 목록을 기반으로 맞춤 추천

**구성**

* 대화 변수: `interested_items`(문자열 배열) = `[]`
* LLM 노드가 사용자 메시지에서 제품 키워드를 추출
* 변수 할당 노드에서 `interested_items`에 추가(append)
* 추천 단계에서 `interested_items` 전체를 LLM에 전달

배열의 **추가(append)** 연산으로 값을 계속 누적합니다.

#### 루프 변수로 상세 리서치

한 번의 검색으로 부족하면 추가 검색을 반복합니다.

**동작 방식**

> 사용자: "재택근무 정책이 어떻게 되나요?"\
> 1회차: 지식 검색 → "재택근무 신청 방법" 발견 → 루프 변수에 저장\
> → LLM: "신청 방법은 찾았지만, 대상자 기준과 장비 지원 정보가 부족합니다"\
> 2회차: "재택근무 대상자"로 재검색 → 결과 추가 저장\
> → LLM: "대상자 기준도 찾았습니다. 충분합니다" → 루프 종료\
> 최종: 수집된 정보를 종합하여 답변

**구성**

```
시작 → 루프 → [지식 검색 → LLM (평가 + 다음 검색어 생성) → 변수 할당] → LLM (종합 답변) → 답변
```

* 루프 변수: `collected`(문자열 배열) = `[]`, `enough`(불리언) = `false`
* 지식 검색 노드: 검색어로 자료 탐색
* LLM 노드: 지금까지 모인 자료(`collected`)를 보고, 충분한지 판단. 부족하면 다음에 찾아볼 검색어를 제시
* 변수 할당 노드: 검색 결과를 `collected`에 추가(append). 충분하다면 `enough`를 `true`로 변경
* 중단 조건: `enough` = `true`

루프 변수에 결과를 누적하고 이를 LLM에 전달합니다.\
LLM은 수집한 내용과 부족한 내용을 비교해 다음 검색을 결정합니다.
