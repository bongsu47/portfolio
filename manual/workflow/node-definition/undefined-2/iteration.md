# 반복

반복 노드는 배열의 각 항목에 같은 작업을 실행합니다.\
순서대로 처리하거나 병렬로 동시에 처리할 수 있습니다.

<figure><img src="../../../../.gitbook/assets/image (649).png" alt="" width="476"><figcaption></figcaption></figure>

### 배열

배열은 여러 값을 하나의 목록으로 묶은 데이터입니다.

예를 들어 검색 키워드 세 개는 다음처럼 표현합니다.

```
["AI 트렌드 2025", "생성형 AI 활용 사례", "LLM 비교"]
```

배열 안의 각 값을 **항목**이라고 합니다.\
배열은 코드 노드, 지식 검색, 문서 추출기 등에서 생성됩니다.

반복 노드는 다음 배열 타입을 지원합니다.

| 타입     | 설명              | 예시                                |
| ------ | --------------- | --------------------------------- |
| 문자열 배열 | 텍스트 목록          | `["사과", "바나나", "딸기"]`             |
| 숫자 배열  | 숫자 목록           | `[85, 92, 78, 95]`                |
| 객체 배열  | 여러 속성을 가진 항목 목록 | `[{name: "김철수", score: 85}, ...]` |
| 파일 배열  | 업로드된 파일 목록      | `sys.files`                       |

문자열이나 숫자 같은 단일 값은 사용할 수 없습니다.

### 역할

여러 데이터에 같은 작업을 적용할 때 사용합니다.

예를 들어 LLM이 검색 키워드 다섯 개를 생성합니다.

```
["AI 트렌드", "생성형 AI 활용", "LLM 비교", "프롬프트 엔지니어링", "AI 에이전트"]
```

반복 노드 안에 웹 검색 노드를 하나 배치합니다.\
각 키워드로 검색한 뒤 모든 결과를 배열로 반환합니다.

#### 병렬 연결과 비교

병렬 연결도 비슷한 작업을 수행합니다.\
실행 횟수를 정하는 방식이 다릅니다.

병렬 연결은 워크플로우를 만들 때 경로 수가 고정됩니다.\
예를 들어 웹 검색 노드를 세 개 연결하면 항상 세 번 검색합니다.

반복 노드는 배열 크기만큼 실행합니다.\
키워드가 세 개면 세 번, 일곱 개면 일곱 번 실행합니다.

|        | 병렬 연결                    | 반복 노드                           |
| ------ | ------------------------ | ------------------------------- |
| 실행 횟수  | 워크플로우 설계 시 고정 (예: 항상 3개) | 배열 크기에 따라 유동적 (3개일 수도, 10개일 수도) |
| 적합한 상황 | 처리할 항목이 미리 정해져 있을 때      | 실행 시점에 항목 수가 결정될 때              |
| 설정     | 노드를 직접 여러 개 배치           | 노드 하나만 배치, 배열 입력                |

{% hint style="info" %}
**반복 노드와 루프 노드**

* **반복 노드**: 배열의 각 항목을 처리합니다. 실행 횟수는 배열 크기로 정해집니다.
* **루프 노드**: 조건을 충족할 때까지 반복합니다. 실행 횟수는 조건에 따라 달라집니다.

배열 처리에는 반복 노드를 사용하세요.\
조건 기반 반복에는 루프 노드를 사용하세요.
{% endhint %}

### 설정

<figure><img src="../../../../.gitbook/assets/image (650).png" alt=""><figcaption></figcaption></figure>

#### 입력 변수

반복할 배열 변수를 선택합니다. 배열 변수만 선택할 수 있습니다.\
빈 배열(`[]`)은 내부 노드를 실행하지 않고 빈 배열을 반환합니다.

#### 반복 내부 노드

반복 노드 안의 `+`로 노드를 배치합니다.\
내부 노드는 배열의 각 항목마다 실행됩니다.

반복 노드에서는 두 특수 변수를 사용할 수 있습니다.

| 변수      | 설명                 | 예시                                        |
| ------- | ------------------ | ----------------------------------------- |
| `item`  | 현재 처리 중인 항목의 값     | 배열이 `["A", "B", "C"]`일 때, 첫 번째 반복에서 `"A"` |
| `index` | 현재 항목의 순서 (0부터 시작) | 첫 번째: 0, 두 번째: 1, 세 번째: 2                 |

변수 목록에서 `item`과 `index`를 선택할 수 있습니다.\
예를 들어 `{{#반복_1.item#}}`으로 현재 항목을 참조합니다.

{% hint style="info" %}
**index 활용**

`index`는 처리 중인 항목의 순서를 나타냅니다.

* LLM 프롬프트에서 문서에 번호를 매길 때
* 첫 번째 항목에만 별도 작업을 적용할 때
* 진행 상황을 결과에 포함할 때
{% endhint %}

#### 출력 변수

각 반복에서 저장할 결과 변수를 선택합니다.\
모든 반복이 끝나면 결과를 배열로 반환합니다.

예를 들어 문서 세 개를 요약합니다.

* 입력: `["문서1 전문...", "문서2 전문...", "문서3 전문..."]`
* 출력 변수로 LLM 노드의 `text`를 선택
* 결과: `["문서1 요약", "문서2 요약", "문서3 요약"]`

#### 병렬 모드

기본값은 직렬 실행입니다. 병렬 실행으로 변경할 수 있습니다.

**직렬 실행**

항목을 하나씩 순서대로 처리합니다.

* 결과 배열은 입력 순서를 유지합니다.
* 전체 시간은 각 항목 처리 시간의 합입니다.

**병렬 실행**

**병렬 모드**를 활성화하면 여러 항목을 동시에 처리합니다.

동시 실행 수는 한 번에 처리할 최대 항목 수입니다. 범위는 1\~10입니다.\
예를 들어 10으로 설정하면 항목을 최대 10개씩 처리합니다.

항목이 30개이고 동시 실행 수가 10이면 다음처럼 실행합니다.

* 10개를 동시에 처리합니다.
* 완료되면 다음 10개를 처리합니다.
* 마지막 10개까지 모두 처리합니다.

항목이 더 많아도 동시 실행 수만큼 나누어 처리합니다.

| 항목                | 직렬     | 병렬 (동시 실행 수: 10) |
| ----------------- | ------ | ---------------- |
| 30개의 문서 요약 (각 5초) | 약 150초 | 약 15초 (10개씩 3번)  |

병렬로 처리해도 결과 배열은 입력 순서를 유지합니다.

{% hint style="info" %}
**병렬 실행 선택**

**병렬 실행이 적합한 경우**

* 각 항목이 서로 독립적일 때
* LLM 요약, API 호출, 파일 변환처럼 시간이 오래 걸릴 때
* 처리 속도가 중요할 때

**직렬 실행이 적합한 경우**

* 이전 항목의 결과가 다음 항목에 필요할 때
* 외부 API에 호출 횟수 제한이 있을 때
* 처리 순서가 로직에 영향을 줄 때
{% endhint %}

{% hint style="warning" %}
**병렬 실행 시 주의**

병렬 모드에서 내부에 **답변 노드**를 배치할 때 주의하세요.\
여러 항목이 동시에 답변을 생성하면 결과가 섞일 수 있습니다.
{% endhint %}
