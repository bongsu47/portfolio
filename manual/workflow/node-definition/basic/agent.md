# 에이전트

<figure><img src="../../../../.gitbook/assets/image (832).png" alt=""><figcaption></figcaption></figure>

에이전트 노드는 AI가 도구를 선택해 호출하고, 결과를 바탕으로 답변을 완성하는 노드입니다.

LLM 노드와 달리 **판단 → 도구 호출 → 결과 확인 → 재판단**을 반복합니다.

웹 검색, 외부 API 조회, 워크플로우 도구 실행처럼 다음 행동을 판단해야 하는 작업에 사용합니다.

### 역할

사용자 요청을 이해하고 필요한 도구를 선택해 호출합니다.

결과를 반영해 목표를 달성할 때까지 다음 행동을 결정합니다. 마지막에는 결과를 종합해 최종 답변을 생성합니다.

반복 호출과 도구 실패를 감지하면 실행을 안전하게 중단합니다.

### LLM 노드와 비교

| 구분         | LLM 노드                    | 에이전트 노드                  |
| ---------- | ------------------------- | ------------------------ |
| **실행 방식**  | 프롬프트를 한 번 호출하고 종료 (단발 호출) | 도구 호출과 결과 반영을 반복 (반복 실행) |
| **도구 사용**  | 없음                        | 모델이 스스로 도구를 선택·호출        |
| **적합한 작업** | 정해진 프롬프트로 한 번에 답하면 되는 작업  | 중간 결과에 따라 다음 행동이 달라지는 작업 |

### 설정

#### 모델 선택

워크스페이스에 등록한 LLM 모델 중 하나를 선택합니다.

도구를 사용하려면 **Function Calling**을 지원하는 모델을 선택하세요. 이미지 분석에는 비전 지원 모델이 필요합니다.

> _**ℹ️ 참고**_
>
> _도구 호출을 지원하지 않는 모델을 선택하면 답변은 생성되지만 도구를 호출하는 자율 실행은 동작하지 않습니다. 이미지 분석이 필요하다면 아래 **비전** 항목을 참고하세요._

#### 실행 모드

질문 복잡도에 따라 실행 경로를 선택합니다.

| 모드             | 설명                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **auto (기본값)** | 질문의 복잡도를 평가해 실행 경로를 자동 선택합니다. 단순 질의는 실행기(Executor) 단독, 중간 복잡도는 계획(Planner) 추가, 복잡한 질의는 계획·조사·검토(Planner·Researcher·Reviewer)까지 포함합니다. |
| **fast**       | 복잡도 평가 없이 실행기 하나로 곧바로 도구 호출 루프를 돕니다. 응답 지연을 줄이고 싶을 때 사용합니다.                                                                           |

사고 과정 표시를 켜면 에이전트의 중간 판단 과정을 스트림으로 확인할 수 있습니다.

> _**ℹ️ 참고**_
>
> _현재 지원하는 도구 사용 방식은 **Function Calling** 하나입니다. ReAct 등 별도 추론 전략 선택 기능은 없습니다. auto/fast는 추론 전략이 아니라 "얼마나 단계를 나눠 실행할지"를 정하는 실행 경로 선택입니다._

#### 도구

에이전트가 실행할 도구를 연결합니다.

| 종류                      | 설명                    |
| ----------------------- | --------------------- |
| **내장 도구 (builtin)**     | 플랫폼이 기본 제공하는 도구       |
| **API 도구 (api)**        | 관리자가 구성한 커스텀 API 도구   |
| **워크플로우 도구 (workflow)** | 발행된 워크플로우를 하나의 도구로 실행 |
| **MCP 도구 (mcp)**        | MCP로 연결된 외부 도구        |
| **커넥터 도구 (connector)**  | 사용자별 OAuth 커넥터 도구     |

각 도구는 실행 전에 일부 입력값을 고정할 수 있습니다. 폼 입력값은 미리 지정합니다. 모델이 채우는 값도 **고정** 모드에서 지정할 수 있습니다.

일부 도구를 준비하지 못하면 해당 도구만 제외합니다. 사용할 수 있는 도구로 실행을 계속합니다.

> _**ℹ️ 참고**_
>
> _워크플로우를 직접 실행하는 중 승인 대상 도구가 호출되면 노드가 **일시정지(PAUSED)** 상태가 되고, 승인 입력 후 재개됩니다. 차단(blocked)으로 지정된 도구는 항상 실행되지 않습니다._

#### 지식

연결한 지식은 **지식 검색 도구**로 자동 변환됩니다. 에이전트는 필요할 때 지식을 검색해 답변에 활용합니다.

지식별 검색 방식과 메타데이터 필터를 설정할 수 있습니다. 앱과 지식의 권한을 모두 충족하는 지식만 사용할 수 있습니다.

#### 실행 제어

반복 실행을 제한해 무한 반복과 과도한 비용을 방지합니다.

| 파라미터            | 기본값 | 범위        | 설명                                                                 |
| --------------- | --- | --------- | ------------------------------------------------------------------ |
| **최대 반복 횟수**    | 10  | 1 \~ 25   | 도구를 호출하는 반복의 최대 횟수. 예산 소진 시 도구 없이 결과를 종합하는 turn이 한 번 더 허용될 수 있습니다. |
| **최대 실행 시간(초)** | 300 | 0 \~ 1800 | 전체 실행 시간 상한. 0으로 두면 이 제한을 끕니다.                                     |

반복당 도구 호출 수는 내부 기본값으로 관리합니다. 최대 5개까지 호출하며, 이 값은 노드 화면에서 설정할 수 없습니다.

{% hint style="info" %}
간단한 조회·요약은 반복 횟수를 낮게(예: 3\~5) 두어 비용을 줄이고, 여러 도구를 순차로 써야 하는 조사형 작업은 높게(예: 10\~20) 두어 중간에 끊기지 않게 하세요.
{% endhint %}

#### 프롬프트 구성

에이전트는 지시, 질의, 컨텍스트로 실행 지침을 구성합니다.

| 요소                   | 설명                                                                         |
| -------------------- | -------------------------------------------------------------------------- |
| **지시 (instruction)** | 에이전트의 기본 역할과 규칙을 정의하는 시스템 지침. `{{#노드.변수#}}` 형태로 이전 노드의 변수 값을 끼워 넣을 수 있습니다. |
| **질의 (query)**       | 에이전트가 처리할 사용자 요청. 노드에 직접 입력하거나 변수로 받아 동적으로 구성합니다.                          |
| **컨텍스트 (context)**   | 질의와 별도로 참고 맥락을 문자열로 전달합니다.                                                 |

실행 시에는 진행, 종료, 오류 처리에 관한 기본 지침을 자동으로 추가합니다.

{% hint style="info" %}
응답을 JSON으로 받으려면 **구조화 출력(Structured Output)** 을 켜세요. 지시에 "JSON 객체 하나만 출력"하도록 안내가 추가되고 최종 텍스트를 파싱해 별도 출력에 담습니다. 단, 모델 API 차원에서 형식을 강제하는 방식이 아니라 최종 텍스트를 최선의 방식으로 파싱하는 것이므로, 프롬프트에 원하는 형식을 구체적으로 함께 제시하세요.
{% endhint %}

#### 메모리

메모리는 이전 대화를 전달해 대화 맥락을 유지합니다.

대화 세션에서는 대화 메모리를 사용합니다. 단발성 실행에서는 해당 실행 중에만 임시 맥락을 유지합니다.

윈도우 크기는 유지할 최근 대화 수입니다. 기본값은 **5**입니다. 맥락이 길어지면 자동으로 압축합니다.

#### 비전

비전을 켜면 파일 변수의 이미지를 에이전트에 전달해 분석합니다.

선택한 모델이 이미지 입력을 지원하지 않으면 이미지를 제외하고 텍스트만 처리합니다. 이미지 분석에는 비전 지원 모델을 선택하세요.

전달한 이미지는 사용자 메시지에 포함됩니다. 파일 입력을 받는 도구에는 도구 인자로 전달될 수 있습니다.

#### 출력 변수

정상 실행되면 다음 변수를 반환합니다.

| 변수              | 내용                                                                           |
| --------------- | ---------------------------------------------------------------------------- |
| **text**        | 에이전트가 생성한 최종 답변                                                              |
| **usage**       | 토큰 사용량 정보 (prompt / completion / total)                                      |
| **tool\_calls** | 실행 중 호출한 도구의 이름·입력·출력·오류 여부를 순서대로 기록한 배열. 도구 결과(observation)는 각 항목 출력에 담깁니다. |
| **json**        | 구조화 출력을 켰을 때, 최종 텍스트를 JSON으로 파싱한 결과                                          |
| **files**       | 출력 항목으로 존재하지만 현재 구현에서는 항상 빈 배열                                               |

{% hint style="info" %}
현재 `files` 출력은 비어 있으므로, 에이전트나 도구가 생성한 파일이 이 출력을 통해 다음 노드로 전달되지 않습니다. 파일 전달을 전제로 워크플로우를 설계하지 마세요. 도구가 무엇을 했는지 추적하려면 `tool_calls` 출력을 확인하세요.
{% endhint %}
