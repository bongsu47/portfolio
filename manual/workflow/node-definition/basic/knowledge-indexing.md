# 인덱싱 상태 확인

인덱싱 상태 확인 노드는 지식에 추가한 문서의 인덱싱 상태를 확인합니다.\
지식 추가 뒤 인덱싱 완료 여부를 워크플로우에서 확인할 수 있습니다.

<figure><img src="../../../../.gitbook/assets/image (43).png" alt="" width="290"><figcaption></figcaption></figure>

### 역할

문서를 지식에 추가해도 바로 검색할 수는 없습니다.\
문서를 분할하고 검색 가능한 형태로 변환하는 인덱싱이 필요합니다.\
문서 크기에 따라 수 초에서 수십 분이 걸릴 수 있습니다.

이 노드는 인덱싱 진행 상태를 반환합니다.

### 사용 시점

지식 추가 뒤 바로 검색해야 할 때 사용합니다.\
인덱싱이 완료될 때까지 상태를 확인합니다.

* 지식 추가 → **인덱싱 상태 확인** → 완료 후 지식 검색
* 루프 노드와 연결해 완료될 때까지 반복 확인

{% hint style="info" %}
**기존 문서에 추가한 경우**

기존 문서에 내용을 이어 붙이면 인덱싱이 즉시 완료됩니다.\
이 경우에는 상태 확인 노드가 필요하지 않습니다.

새 문서를 추가해 `status`가 `processing`일 때 사용하세요.
{% endhint %}

### 설정

노드를 선택하면 설정 패널이 열립니다.\
**입력 변수**에서 하나 이상의 값을 입력합니다.

#### 데이터셋 ID

확인할 지식의 고유 ID입니다.\
입력하면 해당 지식의 모든 문서 상태를 확인합니다.\
특정 문서만 확인하려면 배치 ID 또는 문서 ID 목록을 함께 사용하세요.

#### 배치 ID

지식 추가 시 생성되는 작업 묶음 ID입니다.\
같은 실행에서 함께 추가한 문서는 같은 배치 ID를 가집니다.\
예를 들어 파일 세 개를 추가하면 배치 ID 하나로 모두 확인합니다.

#### 문서 ID 목록

확인할 개별 문서의 ID 목록입니다.\
여러 ID는 쉼표(`,`)로 구분합니다.

#### 입력 변수 연결

세 입력값은 지식 추가 노드의 출력값을 사용합니다.

지식 추가 노드는 결과를 배열 형태의 `json` 변수에 저장합니다.\
`dataset_id`, `batch` 같은 필드는 코드 노드에서 분리한 뒤 연결합니다.

지식 추가와 인덱싱 상태 확인 사이에 코드 노드를 배치합니다.

```python
def main(json_result: list) -> dict:
    result = json_result[0]
    return {
        "dataset_id": result["dataset_id"],
        "batch": result["batch"],
        "document_ids": ",".join(result["document_ids"])
    }
```

* 입력: 지식 추가 노드의 `json`을 `json_result`에 연결
* 출력: `dataset_id`, `batch`, `document_ids`를 각각 분리

> 지식 추가 → **코드 (값 추출)** → 인덱싱 상태 확인

| 인덱싱 상태 확인 입력 | 코드 노드 출력       | 설명                     |
| ------------ | -------------- | ---------------------- |
| 데이터셋 ID      | `dataset_id`   | 지식의 고유 ID              |
| 배치 ID        | `batch`        | 같은 시점에 추가된 문서 묶음 ID    |
| 문서 ID 목록     | `document_ids` | 추가된 문서의 ID (쉼표 구분 문자열) |

가장 간단한 방법은 데이터셋 ID만 연결하는 것입니다.\
해당 지식의 모든 문서 상태를 확인합니다.

방금 추가한 문서만 확인하려면 배치 ID 또는 문서 ID 목록을 함께 연결하세요.

### 출력 변수

| 변수      | 타입             | 설명            |
| ------- | -------------- | ------------- |
| `text`  | String         | 상태 요약 메시지     |
| `files` | Array\[File]   | 도구가 생성한 파일 목록 |
| `json`  | Array\[Object] | 상세 인덱싱 상태 데이터 |

`json`에는 상세 인덱싱 상태가 포함됩니다.\
주요 필드는 다음과 같습니다.

```
{
  "status": "processing",
  "dataset_name": "상담 기록",
  "total": 3,
  "completed": 1,
  "failed": 0,
  "processing": 2,
  "message": "Indexing in progress: 1/3 completed, 2 processing.",
  "documents": [
    {
      "name": "상담_20250320.txt",
      "status": "completed",
      "segments": 12
    },
    {
      "name": "상담_20250321.txt",
      "status": "indexing",
      "progress": 80
    }
  ]
}
```

#### 전체 상태

| 상태           | 의미                               |
| ------------ | -------------------------------- |
| `completed`  | 모든 문서의 인덱싱이 완료되었습니다              |
| `processing` | 인덱싱이 진행 중인 문서가 있습니다              |
| `partial`    | 일부 문서는 완료되었지만, 일부는 실패하거나 진행 중입니다 |
| `error`      | 모든 문서의 인덱싱이 실패했습니다               |

#### 개별 문서 상태

| 상태          | 의미       | 진행률  |
| ----------- | -------- | ---- |
| `waiting`   | 대기 중     | 0%   |
| `parsing`   | 파일 분석 중  | 20%  |
| `cleaning`  | 데이터 정리 중 | 40%  |
| `splitting` | 텍스트 분할 중 | 60%  |
| `indexing`  | 인덱싱 중    | 80%  |
| `completed` | 완료       | 100% |
| `error`     | 실패       | -    |

완료한 문서에는 분할된 조각 수인 `segments`가 포함됩니다.\
실패한 문서에는 오류 원인인 `error`가 포함됩니다.

### 활용 예시

지식 추가 후 바로 검색해야 하면 루프 노드로 완료를 기다릴 수 있습니다.

> 지식 추가 → 코드 (값 추출) → **루프 시작** → 인덱싱 상태 확인 → 조건 분기 (completed이면 루프 종료) → **루프 끝** → 지식 검색 → 답변

조건 노드에서 `status`가 `completed`인지 확인합니다.\
완료되지 않았다면 루프를 반복합니다.
