# 의도분류

의도 분류 노드는 사용자 질문의 의도를 AI가 판단합니다.\
분류 결과에 따라 워크플로우를 서로 다른 경로로 분기합니다.

<figure><img src="../../../../.gitbook/assets/image (44).png" alt="" width="274"><figcaption></figcaption></figure>

### 역할

미리 정의한 의도 중 하나로 질문을 분류합니다.\
각 의도에 다음 노드를 연결하면 유형별 처리를 구성할 수 있습니다.

예를 들어 사내 인사 챗봇은 다음처럼 처리할 수 있습니다.

* “연차 며칠 남았어?” → **인사 관련 질의** → 지식 검색과 LLM으로 답변
* “모니터 고장났는데 어디에 말하면 돼?” → **문의 사항 접수** → 담당 부서에 메일 발송

의도별 흐름은 다음과 같이 연결할 수 있습니다.

> 시작 → **의도 분류** → 인사 관련 질의 → 지식 검색 → LLM → 답변\
> 　　　　　　　　　　　└→ 문의 사항 접수 → LLM → 메일 발송 도구 → 답변

### 조건 노드와 비교

두 노드는 모두 워크플로우를 분기합니다.\
분기 기준은 서로 다릅니다.

**조건 노드**는 변수 값을 규칙으로 비교합니다.\
`포함`, `같음`, `보다 큼` 같은 조건을 직접 설정합니다.\
예를 들어 `status`가 `active`이면 A 경로로 분기합니다.

**의도 분류 노드**는 AI가 텍스트 의미를 판단합니다.\
표현이 달라도 같은 의도로 분류할 수 있습니다.\
예를 들어 연차 신청, 휴가, 남은 연차 질문을 모두 **인사 관련 질의**로 분류합니다.

| 구분     | 의도 분류          | 조건 노드      |
| ------ | -------------- | ---------- |
| 분기 기준  | AI가 텍스트 의미를 판단 | 값을 규칙으로 비교 |
| 비용     | AI 모델 호출 비용 발생 | 비용 없음      |
| 속도     | 모델 호출 시간 필요    | 즉시 처리      |
| 적합한 상황 | 질문 유형 파악       | 명확한 값 비교   |

자연어 의도를 파악할 때는 의도 분류를 사용하세요.\
명확한 값 비교에는 조건 노드가 더 적합합니다.

### 설정

의도 분류 노드를 선택하면 설정 패널이 열립니다.

<figure><img src="../../../../.gitbook/assets/image (662).png" alt="" width="328"><figcaption></figcaption></figure>

#### 모델

의도를 판단할 AI 모델을 선택합니다.\
모델 이름 옆 설정 아이콘에서 Temperature 같은 파라미터를 조정합니다.

단순한 분류에는 가벼운 모델로도 충분합니다.\
의도가 많거나 경계가 모호하면 고성능 모델을 사용하세요.

#### 입력 변수

분류할 텍스트가 담긴 변수를 선택합니다.

일반적으로 원본 사용자 질문인 `sys.query`를 선택합니다.\
이전 LLM 노드가 처리한 텍스트도 사용할 수 있습니다.

#### 비전

비전을 켜면 이미지도 함께 분석합니다.\
이 기능은 비전을 지원하는 모델에서만 사용할 수 있습니다.

예를 들어 장비 사진과 “이거요”를 받으면 문의 접수로 분류할 수 있습니다.

#### 의도

분류할 의도와 설명을 정의합니다.\
기본 의도는 두 개입니다. `+` 버튼으로 의도를 추가할 수 있습니다.

각 의도에는 해당 질문의 범위를 설명합니다.\
AI는 이 설명을 기준으로 가장 적합한 의도를 선택합니다.

사내 인사 챗봇의 의도는 다음처럼 정의할 수 있습니다.

| 의도  | 설명 예시                                             |
| --- | ------------------------------------------------- |
| 의도1 | 연차, 휴가, 급여, 복리후생, 근태, 인사 제도 관련 질문                 |
| 의도2 | 시설 고장, 장비 요청, 업무 불편 사항, 건의 사항 등 담당 부서에 전달이 필요한 문의 |
| 의도3 | 위에 해당하지 않는 일반 대화, 인사, 잡담                          |

의도를 추가하면 해당 의도의 연결 포인트가 생깁니다.\
각 포인트에 다른 노드를 연결해 의도별 흐름을 만듭니다.

* **인사 관련 질의** → 지식 검색 → LLM → 답변
* **문의 사항 접수** → LLM → 메일 발송 도구 → 답변
* **기타** → LLM → 답변

{% hint style="info" %}
**의도를 정의하는 방법**

* **구체적으로 작성하세요.** `기타`보다 `일반 대화 및 인사`가 더 정확합니다.
* **의도 수를 제한하세요.** 의도가 10개 이상이면 정확도가 낮아질 수 있습니다.
* **의도 범위를 겹치지 않게 정의하세요.** 각 의도의 경계를 명확히 합니다.
{% endhint %}

#### 프롬프트

분류에 적용할 추가 지침을 작성합니다.\
`/`를 입력해 변수를 삽입할 수 있습니다.

의도만으로 구분하기 어렵다면 경계 규칙을 추가하세요.\
단순한 분류에는 빈 값으로 두어도 됩니다.

인사 챗봇의 지시사항 예시는 다음과 같습니다.

```
## 분류 원칙
- 사용자의 핵심 의도를 기준으로 가장 적합한 의도 1개만 선택한다.
- 두 가지 의도가 섞여 있으면, 더 구체적인 의도를 우선한다.
- 근거가 부족하거나 판단이 어려우면 "기타"를 선택한다.

## 경계 규칙
- 인사 제도/정책에 대한 질문 → "인사 관련 질의"
- 본인의 연차/급여/근태 조회 → "인사 관련 질의"
- 시설/장비 고장 신고 → "문의 사항 접수"
- 업무 환경 개선 건의 → "문의 사항 접수"
- 특정 부서/담당자 연결 요청 → "문의 사항 접수"
- 인사 규정 변경 건의 → "문의 사항 접수" (질의가 아닌 접수)
- 인사, 감사, 잡담 → "기타"
```

의도 간 경계를 구체적으로 정의하면 오분류를 줄일 수 있습니다.\
예를 들어 규정 변경 건의는 질의가 아닌 접수로 처리합니다.

#### 메모리

메모리를 켜면 이전 대화도 함께 고려합니다.

예를 들어 연차를 논의한 뒤 “그럼 어떻게 하면 돼?”를 받습니다.\
이 경우 인사 관련 질의로 더 정확하게 분류할 수 있습니다.

대화 문맥이 중요한 챗플로우에서 사용하세요.

### 출력 변수

| 변수           | 타입     | 설명         |
| ------------ | ------ | ---------- |
| `class_name` | String | 분류된 의도의 이름 |

분류 결과에 따라 노드는 해당 의도의 연결 포인트로 분기합니다.\
`class_name`은 분류된 의도 이름을 이후 노드에서 참조할 때 사용합니다.
