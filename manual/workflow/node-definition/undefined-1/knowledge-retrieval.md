# 지식 검색

지식 검색 노드는 등록된 지식에서 질문과 관련된 정보를 찾습니다.

검색 결과는 LLM이 정확한 답변을 생성할 때 참고 자료로 사용합니다.\
내부 정보나 최신 정보를 활용할 때 사용하세요.

<figure><img src="../../../../.gitbook/assets/image (39).png" alt="" width="288"><figcaption></figcaption></figure>

### 역할

질문의 의미를 바탕으로 관련성이 높은 지식 내용을 찾습니다.\
유사도 검색, 키워드 검색, 하이브리드 검색 방식을 지원합니다.

다음과 같은 질문을 처리할 수 있습니다.

* “반품 절차가 어떻게 되나요?” → 반품 매뉴얼의 관련 내용 검색
* “회의실 예약 방법” → 사내 규정의 예약 절차 검색

검색 결과는 보통 LLM 노드의 컨텍스트에 연결합니다.

{% hint style="info" %}
**지식 검색과 LLM 연결**

지식 검색 노드는 검색 결과 목록만 반환합니다.\
자연스러운 답변을 생성하려면 결과를 LLM 노드의 컨텍스트에 연결하세요.
{% endhint %}

### 설정

지식 검색 노드를 선택하면 설정 패널이 열립니다.

<figure><img src="../../../../.gitbook/assets/image (663).png" alt="" width="331"><figcaption></figcaption></figure>

#### 입력 변수

검색할 질문이 담긴 변수를 선택합니다.

* 일반적으로 원본 사용자 질문인 `sys.query`를 선택합니다.
* LLM으로 질문을 정제하면 검색 정확도를 높일 수 있습니다.

#### 지식 선택

**지식** 영역에서 검색 대상을 선택합니다.\
**지식 검색**을 선택하면 워크스페이스의 지식을 하나 이상 추가할 수 있습니다.

선택한 지식에는 다음과 같은 태그가 표시됩니다.

| 태그   | 의미                          |
| ---- | --------------------------- |
| 공유받음 | 다른 사용자가 만든 지식을 공유받아 사용 중    |
| 리랭크  | 현재 이 지식에 리랭킹 검색 방식이 적용되어 있음 |

{% hint style="info" %}
**여러 지식을 검색하는 방법**

여러 지식은 한 노드에서 함께 검색할 수 있습니다.\
지식별로 별도 노드를 구성할 수도 있습니다.

**한 노드에서 여러 지식 검색**\
결과를 통합하고 전체 Top K만큼 반환합니다.\
예를 들어 두 지식에서 각각 5건을 찾아도, 통합 Top K가 4이면 4건만 반환합니다.

**지식별로 별도 노드 구성**\
각 노드가 독립적으로 검색하고, 각 노드의 Top K만큼 결과를 반환합니다.
{% endhint %}

<figure><img src="../../../../.gitbook/assets/image (33).png" alt="" width="563"><figcaption></figcaption></figure>

|        | 한 노드에 여러 지식                | 노드를 나눠서 각각 검색                |
| ------ | -------------------------- | ---------------------------- |
| 검색 결과  | 통합 Top K로 전체에서 상위 N건       | 지식마다 각각 Top K건 확보            |
| 장점     | 설정이 간단하고, 리랭크 모델로 통합 정렬 가능 | 특정 지식의 결과가 묻히지 않음            |
| 적합한 경우 | 비슷한 주제의 지식을 함께 검색할 때       | 주제가 다른 지식에서 각각 반드시 결과가 필요할 때 |

{% hint style="info" %}
주제가 다른 지식을 함께 검색하면 일부 결과가 제외될 수 있습니다.\
각 지식의 결과가 꼭 필요하면 노드를 분리하세요.
{% endhint %}

#### 개별 지식 검색 설정

지식 이름 옆의 `∨`를 선택하면 검색 설정이 열립니다.

지식마다 검색 방식을 설정할 수 있습니다.\
기본값은 지식 업로드 시 설정한 값을 따릅니다.

<figure><img src="../../../../.gitbook/assets/image (35).png" alt="" width="326"><figcaption></figcaption></figure>

**검색 방법**

검색 방법을 하나 선택합니다.

| 탭             | 설명                                                |
| ------------- | ------------------------------------------------- |
| **유사도**       | 질문의 의미를 이해하여 유사한 내용을 검색합니다. 가장 기본적인 방식입니다.        |
| **키워드**       | 정확한 단어 일치로 검색합니다. 고유명사, 코드명, 제품 번호 등을 찾을 때 적합합니다. |
| **하이브리드 가중치** | 유사도 검색과 키워드 검색을 동시에 수행한 뒤, 두 점수를 비율로 합산합니다.       |
| **하이브리드 리랭크** | 유사도 검색과 키워드 검색을 동시에 수행한 뒤, 리랭킹 모델이 결과를 재정렬합니다.    |

{% hint style="info" %}
**하이브리드 가중치와 리랭크 비교**

두 방식은 모두 유사도와 키워드 검색을 함께 사용합니다.\
검색 결과를 결합하는 방식이 다릅니다.

**하이브리드 가중치**는 두 검색 점수를 지정한 비율로 합산합니다.

> 예: 유사도 가중치 0.7 + 키워드 가중치 0.3\
> 최종 점수 = (유사도 점수 x 0.7) + (키워드 점수 x 0.3)

비율을 직접 조정할 수 있습니다. 추가 모델 호출이 없어 빠릅니다.

**하이브리드 리랭크**는 결과를 모은 뒤 리랭킹 모델로 관련성을 다시 평가합니다.

> 예: 유사도 검색에서 5건 + 키워드 검색에서 5건 = 후보 10건\
> → 리랭킹 모델이 10건을 모두 다시 읽고 관련성 순으로 재정렬

정확도를 높일 수 있습니다. 다만 처리 시간과 비용이 증가합니다.
{% endhint %}

**Top K**

반환할 검색 결과의 최대 건수를 설정합니다.\
숫자를 입력하거나 슬라이더로 조절합니다. 기본값은 **3**입니다.

값이 낮으면 관련 정보를 놓칠 수 있습니다.\
값이 높으면 관련 없는 내용이 답변에 포함될 수 있습니다.

**점수 임계값**

활성화하면 지정한 관련도 점수 이상인 결과만 반환합니다.\
예를 들어 `0.5`를 설정하면 0.5 미만 결과를 제외합니다.

**리랭크 모델**

**하이브리드 리랭크**를 선택하면 설정할 수 있습니다.\
드롭다운에서 사용할 리랭킹 모델을 선택합니다.

{% hint style="info" %}
**리랭킹 모델**

리랭킹 모델은 검색 결과의 순서를 다시 평가합니다.\
1차 검색 결과와 질문의 관련성을 분석해 순서를 재정렬합니다.

현재 지원되는 리랭킹 모델은 다음과 같습니다.
{% endhint %}

#### 다중 지식 설정

지식을 두 개 이상 선택하면 통합 검색 결과 설정이 표시됩니다.

<figure><img src="../../../../.gitbook/assets/image (34).png" alt="" width="331"><figcaption></figcaption></figure>

**Top K**

모든 지식 결과를 합산한 뒤 반환할 최대 건수입니다.\
예를 들어 두 지식에서 각각 4건을 찾아도 Top K가 4이면 상위 4건만 반환합니다.

**점수 임계값**

활성화하면 통합 결과 중 지정한 점수 이상만 반환합니다.

**리랭크 모델**

여러 지식의 결과를 통합해 재정렬할 모델을 선택합니다.\
서로 다른 임베딩 모델을 사용한 지식을 함께 검색할 때 유용합니다.

{% hint style="info" %}
리랭킹 모델은 선택 사항입니다. 설정하지 않으면 각 지식의 검색 점수 기준으로 정렬됩니다.
{% endhint %}

#### 테이블 검색

{% hint style="warning" %}
테이블 검색은 **실험실 기능**입니다.\
관리자가 실험실 설정에서 먼저 활성화해야 합니다.
{% endhint %}

Excel(`.xlsx`), CSV(`.csv`) 등 표 형식 지식에서 사용합니다.\
표의 행과 열 구조를 바탕으로 데이터를 조회합니다.

예를 들어 제품 가격표에서 “A제품의 가격이 얼마야?”를 검색할 수 있습니다.

기능을 활성화하면 표 형식 지식에 **테이블** 검색 방법이 표시됩니다.

### 출력 변수

| 변수       | 타입             | 설명           |
| -------- | -------------- | ------------ |
| `result` | Array\[Object] | 검색된 문서 조각 목록 |

`result`는 관련도 순으로 정렬된 검색 결과 배열입니다.\
각 항목은 다음 구조를 가집니다.

```
[
  {
    "title": "휴가 및 근태 관리 규정",
    "content": "연차 신청은 최소 3일 전에 해야 하며, 팀장 승인 후 확정됩니다. 반차는 당일 오전 9시 이전에 신청할 수 있습니다.",
    "metadata": {
      "dataset_name": "인사 규정",
      "document_name": "휴가 및 근태 관리 규정",
      "score": 0.92,
      "position": 1
    }
  },
  {
    "title": "휴가 및 근태 관리 규정",
    "content": "연차는 입사일 기준으로 매년 15일이 부여되며, 미사용 연차는 다음 해로 이월되지 않습니다.",
    "metadata": {
      "dataset_name": "인사 규정",
      "document_name": "휴가 및 근태 관리 규정",
      "score": 0.85,
      "position": 2
    }
  }
]
```

| 필드                       | 설명                        |
| ------------------------ | ------------------------- |
| `title`                  | 검색된 문서의 제목                |
| `content`                | 검색된 내용 (문서에서 질문과 관련된 부분)  |
| `metadata.dataset_name`  | 이 결과가 속한 지식의 이름           |
| `metadata.document_name` | 이 결과가 속한 원본 문서의 파일명       |
| `metadata.score`         | 관련도 점수 (1에 가까울수록 관련도가 높음) |
| `metadata.position`      | 정렬 순서 (1이 가장 관련도가 높은 결과)  |

일반적으로 결과를 LLM 노드의 컨텍스트에 연결합니다.\
템플릿 노드에서 원하는 형식으로 가공할 수도 있습니다.

### 검색 정확도를 높이는 방법

기본 설정으로 부족하면 워크플로우를 조정해 검색 품질을 개선하세요.

#### 검색 전에 질문 정제

맥락이 부족한 질문은 검색 정확도가 낮을 수 있습니다.\
예를 들어 “그거 어떻게 해?”는 적절한 결과를 찾기 어렵습니다.

지식 검색 전에 LLM으로 질문을 정제하세요.

> 시작 → **LLM (질문 정제)** → 지식 검색 → LLM (답변 생성) → 답변

LLM에 검색에 적합한 형태로 질문을 다시 작성하도록 지시합니다.\
“그거 어떻게 해?”는 “연차 신청 절차와 방법”처럼 구체화할 수 있습니다.

#### 가상 문서로 검색하기

일반 검색은 질문과 문서를 비교합니다.\
두 텍스트의 문체가 다르면 유사도 점수가 낮을 수 있습니다.

HyDE는 가상 답변 문서를 생성한 뒤 이를 검색에 사용합니다.\
LLM에 질문의 예상 답변을 작성하도록 지시합니다.

> 시작 → **LLM (가상 답변 생성)** → 지식 검색 → LLM (답변 생성) → 답변

문서와 문서를 비교하므로 검색 정확도를 높일 수 있습니다.\
다만 LLM 호출이 추가되어 처리 시간과 비용이 증가합니다.

#### 여러 검색어로 병렬 검색

질문을 여러 검색어로 변환해 병렬 검색하면 관련 문서를 더 찾을 수 있습니다.

LLM에 질문을 세 가지 표현으로 변환하도록 지시합니다.\
각 검색어로 지식 검색 노드를 병렬 실행합니다.

> 시작 → **LLM (검색어 3개 생성)** → 코드 노드 (분리) → **지식 검색 x 3 (병렬)** → 결과 합산 → LLM (답변 생성) → 답변

“반품 절차가 어떻게 되나요?”에서는 다음 검색어를 만들 수 있습니다.

* "반품 절차 및 단계"
* "상품 반환 신청 방법"
* "환불 처리 프로세스"

한 검색어에서 찾지 못한 문서를 다른 검색어로 찾을 수 있습니다.

#### LLM으로 검색 결과 필터링

관련 없는 검색 결과는 답변 품질을 낮춥니다.\
지식 검색 뒤에 LLM을 추가해 관련 결과만 선택하도록 지시하세요.

> 시작 → 지식 검색 → **LLM (결과 필터링)** → LLM (답변 생성) → 답변

Top K를 높여 후보를 확보한 뒤 관련 결과만 선택하는 방식입니다.

단순한 서비스에는 기본 설정으로 충분합니다.\
검색 품질이 중요하면 위 방법을 조합해 사용하세요.
