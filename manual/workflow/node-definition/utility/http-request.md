# API 요청

외부 서비스와 데이터를 주고받거나 기능을 연동할 때 사용합니다.

<figure><img src="../../../../.gitbook/assets/image (19).png" alt="" width="288"><figcaption></figcaption></figure>

날씨 조회, 메일 발송, 사내 시스템 연동을 자동화할 수 있습니다.

### 역할

외부 웹 서비스에 요청을 보내고, 응답을 워크플로우 변수로 반환합니다.

예를 들어 다음 작업을 처리할 수 있습니다.

* **공공 데이터 조회**: 날씨, 인구 통계, 부동산 시세를 가져옵니다.
* **외부 SaaS 연동**: Notion 페이지를 만들거나 Jira 티켓을 등록합니다.

{% hint style="info" %}
#### 도구와 API 요청 노드 비교

* **도구**: 미리 구성된 연동 기능입니다. 해당 서비스가 목록에 있으면 먼저 사용하세요.
* **API 요청 노드**: 목록에 없는 서비스를 직접 연동합니다. URL, 헤더, 본문은 API 문서에 맞춰 설정합니다.
{% endhint %}

{% hint style="info" %}
#### API가 무엇인가요?

API(Application Programming Interface)는 시스템 간 데이터 교환 방식입니다.

서비스의 개발자 문서에서 URL과 요청 형식을 확인하세요.
{% endhint %}

### 설정

<figure><img src="../../../../.gitbook/assets/image (21).png" alt="" width="360"><figcaption></figcaption></figure>

#### 1. API

요청 방식과 URL을 지정합니다.

**요청 방식**

왼쪽 메뉴에서 HTTP 메서드를 선택합니다.

| 방식         | 용도        | 쉽게 말하면           |
| ---------- | --------- | ---------------- |
| **GET**    | 데이터 조회    | "이 정보 좀 알려줘"     |
| **POST**   | 데이터 전송/생성 | "이 데이터 좀 처리해줘"   |
| **PUT**    | 데이터 전체 수정 | "이 데이터를 통째로 바꿔줘" |
| **PATCH**  | 데이터 일부 수정 | "이 부분만 고쳐줘"      |
| **DELETE** | 데이터 삭제    | "이거 지워줘"         |
| **HEAD**   | 응답 헤더만 확인 | "내용 말고 상태만 알려줘"  |

대부분 `GET`과 `POST`를 사용합니다. API 문서의 안내를 따르세요.

**URL**

오른쪽 입력란에 요청 URL을 입력합니다.

```
https://api.example.com/weather
```

`/`를 입력하면 이전 노드의 변수를 삽입할 수 있습니다.

```
https://api.example.com/orders/{{order_id}}
```

#### 2. Header

요청 형식과 인증 정보 같은 추가 정보를 설정합니다.

\*\*+\*\*를 선택한 뒤, 왼쪽에 이름과 오른쪽에 값을 입력합니다.

| 이름                | 값                     | 설명                    |
| ----------------- | --------------------- | --------------------- |
| `Content-Type`    | `application/json`    | 보내는 데이터가 JSON 형식임을 알림 |
| `Authorization`   | `Bearer sk-abc123...` | API 인증 토큰 전달          |
| `Accept-Language` | `ko-KR`               | 한국어 응답 요청             |

{% hint style="info" %}
#### 인증이 필요한 API는 어떻게 하나요?

대부분의 외부 API는 헤더로 인증 토큰을 전달합니다.

API 문서에서 Bearer 토큰을 안내한다면 다음과 같이 설정합니다.

* 이름: `Authorization`
* 값: `Bearer 여기에_API_키_입력`

API 키는 실행 조건의 환경 변수에 저장한 뒤 참조하세요.
{% endhint %}

각 입력란에서 `/`를 입력하면 변수를 삽입할 수 있습니다. 필요 없는 항목은 휴지통으로 삭제합니다.

#### 3. Params

URL 뒤에 붙는 검색 조건입니다. 주로 `GET` 요청에서 사용합니다.

\*\*+\*\*를 선택한 뒤, 이름과 값을 입력합니다.

다음처럼 설정할 수 있습니다.

| 이름     | 값       |
| ------ | ------- |
| `city` | `Seoul` |
| `lang` | `kr`    |

요청 URL은 `https://api.example.com/weather?city=Seoul&lang=kr`이 됩니다.

#### 4. Body

요청 본문에 보낼 데이터입니다. 주로 `POST`, `PUT`, `PATCH` 요청에서 사용합니다.

오른쪽 메뉴에서 데이터 형식을 선택합니다.

| 형식                        | 설명              | 언제 쓰나요?                       |
| ------------------------- | --------------- | ----------------------------- |
| **none**                  | 본문 없음           | GET 요청 등 데이터를 보낼 필요 없을 때      |
| **json**                  | JSON 형식         | 가장 일반적. 대부분의 API가 이 형식을 사용합니다 |
| **form-data**             | 폼 형식 (파일 첨부 가능) | 파일을 업로드할 때                    |
| **x-www-form-urlencoded** | URL 인코딩된 폼      | 간단한 폼 데이터를 보낼 때               |
| **raw-text**              | 일반 텍스트          | 특수한 형식이 필요할 때                 |

**JSON 본문**

`json`을 선택한 뒤, JSON 형식으로 데이터를 작성합니다.

```json
{
  "to": "user@example.com",
  "subject": "주문 완료 안내",
  "body": "주문이 정상적으로 접수되었습니다."
}
```

편집기에서 `/`를 입력하면 변수를 삽입할 수 있습니다.

**form-data와 x-www-form-urlencoded**

이름-값 쌍으로 입력합니다. \*\*+\*\*로 항목을 추가합니다.

| 이름        | 값                  |
| --------- | ------------------ |
| `to`      | `user@example.com` |
| `subject` | `주문 완료 안내`         |

#### 5. 타임아웃

외부 서비스의 응답 대기 시간을 설정합니다.

| 설정    | 설명               | 범위      |
| ----- | ---------------- | ------- |
| 연결 시간 | 서버와 연결이 될 때까지 대기 | 0\~300초 |
| 수신 시간 | 응답을 받을 때까지 대기    | 0\~120초 |
| 송신 시간 | 요청을 보낼 때까지 대기    | 0\~60초  |

{% hint style="info" %}
응답이 느리면 수신 시간을 늘리세요. 빠른 API는 시간을 줄여 대기 시간을 단축할 수 있습니다.
{% endhint %}

### 출력 변수

요청이 완료되면 다음 변수를 반환합니다.

| 변수            | 설명               |
| ------------- | ---------------- |
| `body`        | 응답 내용 (텍스트)      |
| `status_code` | 응답 상태 코드 (숫자)    |
| `headers`     | 응답 헤더 정보 (JSON)  |
| `files`       | 응답이 파일인 경우 파일 목록 |

### 주요 상태 코드

| 코드  | 의미      | 쉽게 말하면            |
| --- | ------- | ----------------- |
| 200 | 성공      | "요청 잘 처리했어"       |
| 400 | 잘못된 요청  | "보낸 내용에 문제가 있어"   |
| 401 | 인증 실패   | "API 키가 틀렸거나 없어"  |
| 403 | 권한 없음   | "이 요청을 할 권한이 없어"  |
| 404 | 찾을 수 없음 | "요청한 주소가 없어"      |
| 500 | 서버 오류   | "외부 서비스에 문제가 생겼어" |

{% hint style="warning" %}
#### status\_code를 꼭 확인하세요

응답 상태 코드가 `200`이 아니어도 워크플로우는 중단되지 않습니다.

API 요청 뒤에 **조건 노드**를 배치하세요. `status_code`가 `200`인지 확인할 수 있습니다.
{% endhint %}
